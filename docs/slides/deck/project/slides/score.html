6 · How we score and compare

One score that matches what a student sees, and a fair comparison

Score for each run

  • Frames on time: a frame counts only if it and every earlier frame it depends on arrived within 250 ms of capture
  • Time frozen: gaps of 190 ms or more between shown frames, as a share of the 60 s (190 = max(3 × 40, 40 + 150) ms at 25 frames/s)
  • Usable capacity: the highest video bitrate with at most 1% of the time frozen

What we compare

  • S0 one link only · S1 MinRTT · S2 round-robin · S3 redundant · S4 ECF
  • F2 our frame split · F1 whole frames only (no split)
  • A1 F2 over two separate connections
  • R2 F2 told the true link speeds
  • R1 ideal: one link with both speeds added and the lower delay

Fair and checked

  • 8 paired runs per setting: run k streams the same 60 s of the lecture for every scheduler
  • 576 runs in total, raw data for each on GitHub
  • Predictions H1–H5 written down before any run
  • Paired Wilcoxon test, Holm correction over the 5 main comparisons; winning 8 of 8 pairs gives p = 2/2⁸ = 0.0078 before correction
Explain the score with the lecture in mind: a frame that comes late is as bad as a frame that never comes, and because each frame builds on the previous ones, one late frame holds up the ones after it. Then the list of schedulers, then why the comparison is fair.
