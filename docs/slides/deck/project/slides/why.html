9 · The math behind F2

Split each frame so both pieces arrive at the same moment

finish time =

bytes waiting + frame size

link speed

+ one-way delay

bytes waiting = bytes not yet sent on that link + bytes already sitting in its buffer  ·  link speed = bytes acknowledged per second (best of the last 1 s)

Split rule

Pick piece sizes S₁ + S₂ = S (the frame) so that
finish time on link 1 = finish time on link 2.

One equation, one unknown, one answer:

S₁ = ((W₂+S)/R₂ + d₂ − W₁/R₁ − d₁)
    ÷ (1/R₁ + 1/R₂)

W = bytes waiting, R = link speed, d = one-way delay. If one piece would be empty, the whole frame goes to the link that finishes first.

Worked example

Two links at 1.6 Mbit/s = 200 KB/s; one-way delay 15 ms and 75 ms; nothing waiting; a big frame of 85 KB.

  • One link only: 85 ÷ 200 = 425 ms, + 15 ms = 440 ms (too late for 250 ms)
  • The slow link starts 75 − 15 = 60 ms behind; 60 ms × 200 KB/s = 12 KB
  • Fast piece: (85 + 12) ÷ 2 = 48.5 KB → 48.5 ÷ 200 = 242.5 ms + 15 = 257.5 ms
  • Slow piece: 85 − 48.5 = 36.5 KB → 36.5 ÷ 200 = 182.5 ms + 75 = 257.5 ms
  • Both pieces arrive at ≈ 258 ms instead of 440 ms

Worked from the formula. 85 KB is the largest frame in our clip (a camera cut); a typical frame is about 13 KB (2.6 Mbit/s ÷ 25 frames/s).

Finish time on a link is the time to drain what is already waiting plus this frame, at the link's speed, plus the one-way delay. Counting the bytes already sitting in the link's buffer matters: if you only count bytes not yet sent, the fast link always looks empty and gets overloaded. Walk through the example line by line.
